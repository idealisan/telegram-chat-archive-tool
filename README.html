tg-down

Download your Telegram Saved Messages to a local SQLite database and media directory — resumable, link-resolving, disk-aware.

Python 3.10+ Telethon SQLite Resumable

tg-down connects to Telegram using the official MTProto API (via Telethon), iterates your Saved Messages from oldest to newest, saves every message to a local SQLite database, downloads attached media files, and resolves any t.me/… links to capture their referenced content too.

✅ Read-only tg-down never sends, edits, or deletes any messages. It only reads your Saved Messages and fetches linked content.

Quick Start

  1. Get your Telegram API credentials Visit my.telegram.org, log in, go to API development tools, and create an app to get your api_id and api_hash.
  2. Install dependencies 
    pip install -r requirements.txt

    Installs telethon, cryptg (faster crypto), and PySocks (proxy support).

  3. Edit config.json Open config.json and fill in your credentials: 
    {
  "api_id": "12345678",
  "api_hash": "your_api_hash_here"
}
  4. Run 
    python3 main.py
    On first run, Telegram will ask for your phone number and a login code. The session is saved to tg_session.session so future runs skip auth.

Running

python3 main.py

The script will:

  • Load and validate config.json
  • Check disk space ≥ min_free_space_gb
  • Connect to Telegram (prompts for auth on first run)
  • Iterate Saved Messages from oldest → newest
  • Save each message and download its media

Interrupting & Resuming

Press Ctrl+C at any time. Progress is saved atomically after every message (the DB row and the resume cursor are written in a single transaction), so you never lose work.

Media files are downloaded to a .tmp file first, then renamed to the final name only on success — so an interrupted download leaves no corrupt files. On the next startup, any stale .tmp files are automatically deleted and re-downloaded from scratch.

Re-running python3 main.py automatically detects the saved cursor and continues from where it left off:

[INFO] Resuming from message ID > 34921
ℹ️ To restart from scratch Delete messages.db (and optionally media/) then run again. Or run this SQL: DELETE FROM download_state WHERE key='last_saved_message_id';

Moving Files to Another Machine

When disk space runs low, the script stops gracefully. You can move your downloaded media to another machine (NAS, external server, etc.) to free up space, then continue.

Workflow

  1. Script stops when disk is low 
    [STOP] Disk space too low: 3.2 GB free (minimum 10 GB required). Stopping.
  2. Move your media files to free space 
    rsync -av ~/tg-down/media/ user@nas:/tg-archive/
rm -rf ~/tg-down/media/video ~/tg-down/media/document
  3. Resume — answer the startup prompt 
    [NOTICE] 1,243 previously downloaded media file(s) are no longer on disk.
  Skip re-downloading them and keep existing DB records? [y/N]: y
  [OK] Missing files will be skipped.
[INFO] Resuming from message ID > 69894
    The script continues downloading new messages only.

To skip the prompt permanently, set "skip_missing_media": true in config.json.

Re-indexing after moving within the same machine

If you moved files to a different path on the same machine (e.g. an external drive still mounted), run rescan.py to update the DB paths — then tg-down won't re-download anything: 

python3 rescan.py /mnt/external/tg-archive

Or add the path to search_paths in config.json and tg-down will find files there automatically before attempting any download.

ℹ️ DB paths after moving When skip_missing_media is on, the media_path column retains the old (now stale) path. This is intentional — it records where the file was downloaded. Run rescan.py afterwards if you want the column to reflect the new location.

Querying the Database

Open the database with any SQLite client (sqlite3, DB Browser for SQLite, etc.):

sqlite3 messages.db

Useful queries:

-- Count all saved messages
SELECT COUNT(*) FROM messages;

-- Find messages containing a keyword
SELECT message_id, date, text FROM messages
WHERE text LIKE '%recipe%';

-- All messages with downloaded media
SELECT message_id, date, media_type, media_path
FROM messages WHERE media_path IS NOT NULL;

-- See what linked messages were fetched from a saved message
SELECT * FROM resolved_messages
WHERE source_message_id = 34922;

-- Media breakdown by type
SELECT media_type, COUNT(*) FROM messages
GROUP BY media_type ORDER BY COUNT(*) DESC;

Architecture

┌─────────────────────────────────────────────────────┐ │ tg-down │ └─────────────────────────────────────────────────────┘ main.py │ load config · check disk space · start asyncio ▼ downloader.py ──────────────────────────────── Telegram MTProto API │ iter_messages("me", reverse=True) ↕ (via Telethon) │ ├──▶ _get_media_type() classify message │ ├──▶ _download_media() fetch file bytes │ │ │ └──▶ media/<type>/<YYYY>/<MM>/<id>.ext │ ├──▶ extract_tme_links() (utils.py) │ │ found t.me links? │ └──▶ resolve_and_save() ──▶ Telegram API │ └──▶ db.save_resolved_message() │ └──▶ db.save_message() (db.py) └──▶ messages.db (SQLite, WAL mode)

Download Flow

For each message the following steps run in order:

  1. Disk space check — every 50 messages, abort if below minimum
  2. Skip service messages — system events (call ended, user joined) have no content to save
  3. Classify media type — photo / video / document / audio / voice / sticker / animation / video_note
  4. Download media — if enabled, not too large, and type is allowed; skips if file already exists on disk
  5. Extract t.me links — regex scan of message text
  6. Resolve each link — fetch the referenced message via Telegram API, download its media, save to resolved_messages
  7. Save to DB — write message record
  8. Advance cursor — update download_state.last_saved_message_id
  9. Rate limit delay — request_delay_seconds sleep

Link Resolution

When resolve_tme_links is true, the script scans every message's text for two URL patterns:

PatternExampleType
t.me/<username>/<id> https://t.me/durov/123 Public channel / user
t.me/c/<channel_id>/<id> https://t.me/c/1520146127/99 Private channel (must be a member)

The resolved message is saved in the resolved_messages table linked back to its source via source_message_id. Common warn cases:

  • "No user has X as username" — the channel/account was deleted or renamed
  • "Could not find input entity" — private channel you're not a member of

These are harmless — the original saved message is still recorded.

resolved_messages

Content fetched by following t.me links. Same columns as messages plus source_message_id and peer.

Simple key-value store. Currently stores one key: last_saved_message_id — the resume cursor.

Media Layout

media/ photo/ 2024/01/ 123456789.jpg ← named by Telegram message ID 123456790.jpg 2024/02/ 200000001.jpg video/ 2024/01/ 123456791.mp4 document/ 2024/03/ 123456800.pdf ← original extension preserved 123456801.xlsx audio/ voice/ sticker/ animation/ video_note/

File names are {message_id}_{name_hint}{ext}. The name hint comes from (in priority order):

  1. The document's original filename (e.g. report.xlsx → 98765_report.xlsx)
  2. The message text snippet, sanitised for the filesystem (e.g. 98765_My_trip_to_Tokyo.jpg)
  3. Just the message ID if neither is available (e.g. 98765.mp4)

If a cached file exists but its size doesn't match Telegram's reported size, it is deleted and re-downloaded.

Module Reference

main.py

Loads config via utils.load_config(), asserts disk space, then calls asyncio.run(downloader.run_download(cfg)). No logic beyond startup validation.

downloader.py

Contains all async Telethon logic:

  • run_download(cfg) — main loop; creates the TelegramClient, iterates messages, orchestrates saving
  • _get_media_type(message) — classifies a Message object; returns None for non-Message types (e.g. MessageService)
  • _message_to_dict(message) — extracts scalar fields from a Telethon message into a plain dict
  • _download_media(client, message, media_dir, cfg) — downloads a file, enforces size limit, returns relative path
  • resolve_and_save(client, source_id, link_info, cfg) — fetches a linked message and persists it

db.py

Thin SQLite wrapper. All functions open and close a connection via the get_conn() context manager (WAL mode, auto-commit/rollback).

  • init_db(db_path) — creates tables and indexes if they don't exist
  • save_message_and_advance(db_path, data, id) — upsert message row + advance resume cursor atomically
  • save_resolved_message(db_path, source_id, peer, data) — insert resolved link content
  • get_state / set_state — read/write key-value state (resume cursor)
  • get_media_path(db_path, message_id) — return recorded media_path for a message
  • get_missing_media_count(db_path) — count DB records whose media file is absent from disk
  • get_stats(db_path) — return counts for the session summary

utils.py

  • load_config(path) — parse JSON, validate required keys, fill defaults
  • check_disk_space(path, min_gb) — return bool
  • free_space_gb(path) — return float
  • extract_tme_links(text) — regex scan, return list of {url, peer, msg_id} dicts
  • parse_proxy(proxy) — convert URL string or list to Telethon-compatible tuple
  • safe_filename(name, max_len) — strip filesystem-unsafe characters and collapse whitespace

rescan.py

Standalone utility — no async, no Telegram connection needed.

  • Walks one or more directories, extracts message IDs from filenames ({id}_name.ext)
  • Updates media_path in messages and resolved_messages to the new location
  • Reports ambiguous matches (multiple files for same ID) and skips them safely
python3 rescan.py                   # scan media_dir + search_paths from config
python3 rescan.py /mnt/nas/archive  # scan a specific directory
python3 rescan.py /vol1 /vol2       # scan multiple directories

Extending

Add a new media type

Add a detection branch in _get_media_type() in downloader.py and add the type string to the media_types default in utils.py.

Export to another format

The raw_json column stores the full Telethon message object. You can read the DB and json.loads(raw_json) to get every field Telegram exposes:

import sqlite3, json
conn = sqlite3.connect("messages.db")
for row in conn.execute("SELECT raw_json FROM messages"):
    msg = json.loads(row[0])
    print(msg)

Change storage backend

All database operations are isolated in db.py. Replace the SQLite calls with any other store (PostgreSQL, JSON files, etc.) without touching downloader.py.

Add CLI arguments

Import argparse in main.py and override config values after load_config(). For example, --no-media can set cfg["download_media"] = False.

Safety & Rate Limits

⚠️ Protect your session file tg_session.session contains your Telegram login. Treat it like a password — don't share it or commit it to version control.

Built-in safeguards

SafeguardDetails
Read-only API usageOnly get_messages and iter_messages are called. No writes to Telegram.
Rate limit delayrequest_delay_seconds (default 0.5 s) between every API call
FloodWait handlerIf Telegram returns a flood-wait error, the script pauses for exactly the required duration and retries
Automatic reconnectOn any network error the script waits with exponential backoff (5 s → 10 s → … → 5 min cap) and reconnects, resuming from the last saved message
Media download retryPer-file network errors trigger the same backoff loop; the partial .tmp file is deleted before each retry
Atomic file writesFiles are written to filename.tmp and renamed on completion — a crash never leaves a corrupt file that would be mistaken for a complete one
File size validationBefore skipping a cached file, its size is compared to Telegram's reported size; mismatches trigger a re-download
Atomic DB commitThe message row and the resume cursor are written in a single SQLite transaction — no split-brain state on crash
Disk space guardChecked before start and every 50 messages; stops gracefully if free space falls below min_free_space_gb
File size capmax_file_size_mb skips oversized media files
Startup cleanupAny leftover .tmp files from a previous crash are removed at startup
Idempotent downloadsIf a correctly-sized file already exists on disk, it is not re-downloaded
Graceful interruptCtrl+C saves progress before exiting; KeyboardInterrupt is never swallowed mid-operation

Recommendations

  • Keep request_delay_seconds ≥ 0.3 to stay within Telegram's limits
  • If you have many messages with t.me links, consider setting resolve_tme_links to false on first pass, then re-enable for a second pass — link resolution doubles the number of API calls
  • Add tg_session.session and messages.db to .gitignore if working in a git repo
